# Sendust 1.1.0

**Prepared:** 2026-11-22.
**Published:** not yet. Publication is the owner's dispatch of the CI `publish`
workflow; until then, `npm install @sendust/ts` installs `1.0.2`.
**Package:** `@sendust/ts@1.1.0` with `@sendust/ts-<platform>` at the same
version, now seven platform packages.
**Dist-tag:** `latest`.

Two reach improvements, both additive: Linux on musl (Alpine), and OAuth 2.0
authentication. No result, error code, limit, timeout or default changed for
existing callers.

## Installation

```text
npm install @sendust/ts
```

## What changed

- **Linux musl: `linux-x64-musl` and `linux-arm64-musl`.** `node:alpine` is the
  default small Node image, and every install there used to fail closed with
  `CONFIG_NATIVE_UNAVAILABLE`. Both targets are now built and loaded inside a
  musl container on a runner of the same architecture — never cross-compiled —
  and packaged like the rest, with `os`, `cpu` and `libc: ["musl"]`. A glibc host
  keeps installing exactly one package
  ([ADR-0020](../architecture/decisions/0020-per-platform-native-packages.md)).
- **`AUTH XOAUTH2` (RFC 7628).** A tenant that disables password authentication —
  Microsoft 365, Google Workspace — can use Sendust now: `auth: { user,
  accessToken, method: "xoauth2" }`. The token may be a string or a synchronous
  function read once per session, so pool growth gets fresh tokens. XOAUTH2 is
  never chosen implicitly, the `334` error challenge is answered with an empty
  line so the relay's final reply becomes the error, and the token is redacted
  exactly like a password ([ADR-0023](../architecture/decisions/0023-xoauth2-authentication.md)).

Why these two, in this order: they were the two things the
[competitive audit](../research/competitive-landscape.md) found that stop a real
team from installing Sendust — an Alpine container, and an OAuth-only tenant.
Everything else Sendust already does well; nothing else moved.

## Known limitations

- **No real OAuth probe.** The XOAUTH2 path is proven against a scripted relay,
  not against a live Microsoft 365 or Google Workspace tenant; that run needs
  credentials the project does not hold.
- **Bun and Deno on musl are not claimed.** The musl jobs run Node.js only, and
  those runtime checks skip themselves there.
- The owner's Gmail benchmark has still not been re-run against `1.0.x`, so the
  `1.0.1` tail improvement remains a projection.
- Provider quota policies are still not modelled; only observed pushback is.
- `next` stays on `1.0.0`; only `latest` moves with this release.

## Upgrade notes

Drop-in for `1.0.2`. Alpine users no longer need to work around the missing
build. Callers on a password relay change nothing; callers on an OAuth-only
tenant pass a token and set `method: "xoauth2"`.

[story](story.md).
