**Dist-tag:** `latest`.

A resource fix. No API, result, error code, option, or limit changed.

## Installation

```text
npm install @sendust/ts
```

## What changed

- **An idle session is released.** `delivery.sessionIdleMs` used to stop a stale
  session from being *reused*, but nothing closed it: a service that sent one
  message and stayed up kept an authenticated relay connection — and its TLS
  state — until the next send or `close()`. The pool now retires every idle
  native session once the window passes (30 s by default), quitting politely and
  dropping it, and a later message dials fresh. `close()` still releases
  everything immediately.
- **A rejected option leaves nothing behind.** `createTransport` built its first
  native transport before validating `delivery.*`, so an out-of-range value threw
  with a native object already created and never closed. Validation now runs
  first.
- **Close and the pool no longer overlap.** A transport that finished a send
  while the transport was closing could be pushed back into the idle list the
  close path already owned. Only an open engine re-pools a session now.

Why: `1.0.0` and `1.0.1` reported the idle window in the docs as the point where
a session stops being reused, while the socket itself stayed open for the life
of the transport. That is a leak for any long-lived service that sends
infrequently, which is the common shape of a transactional sender.

## Known limitations

- The owner's Gmail comparison has still not been re-run against `1.0.x`; the
  expected improvement from `1.0.1` remains a projection in the
  [real-relay analysis](../qa/real-relay-optimization.md).
- A released session is dropped rather than pooled for a later burst, so a
  sender whose gaps exceed `delivery.sessionIdleMs` pays a fresh handshake per
  burst. That is the intended trade: a bounded pool, not a permanently warm one.
- Provider quota policies are still not modelled; only observed pushback is.

## Upgrade notes

Drop-in for `1.0.1`. A service that was relying on the connection staying open
between widely spaced sends now reconnects instead; no code change is needed.
Raise `delivery.sessionIdleMs` if a handshake per burst is too expensive.

See the [release gate record](../gates/release-1.0.2.md) and the
[story](story.md).
