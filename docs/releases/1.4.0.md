# Sendust 1.4.0

**Released:** pending — prepared 2026-11-25, for the CI `publish` job over OIDC,
tag `v1.4.0`.
**Package:** `@sendust/ts@1.4.0` with `@sendust/ts-<platform>` at the same
version.
**Dist-tag:** `latest`.

The audit's delete-or-wire decisions. One owner per contract, two documented
fields that are now produced, and one code deprecated rather than deleted.

## Installation

```text
npm install @sendust/ts
```

## What changed

### Two documented details are produced

- **`details.recipient`.** An `RCPT` reply that is neither an acceptance nor an
  ordinary refusal now names the address it is about; before, the address was
  known where the error was built and dropped anyway.
- **`details.smtpEnhancedCode`.** A relay that explains itself with an RFC 3463
  code — `535 5.7.8` — now carries that `5.7.8` at AUTH and at the
  transaction's stages. A reply without one adds nothing, so `details` reports
  only what the relay sent.

Both fields were documented and unproducible, so this makes the error model and
the guides describe the adapter rather than a wish.

### One owner per rule

- **The core's `lifecycle` module is gone.** The binding owns the transport
  state machine (`AtomicU8` plus one slot); the core copy had no non-test
  caller, so its tests described a machine no caller reached.
  `SendDeadlines` stays public and moves to `config`, where it is defined.
- **`validate_in_order` and its module are gone.** Precedence is the order in
  which `OutgoingMessage::validate` runs its stages, which is what has always
  decided the error a caller sees.

No public API, result, error code, limit or default changes. The core is
internal and unpublished, so this is a cleanup rather than a surface change.

### `PROTOCOL_REJECTED` is deprecated

No path produces it: a definitive refusal is a `rejected` outcome, and a
malformed reply is `PROTOCOL_UNEXPECTED_RESPONSE`. Codes are append-only within
a major version, so it stays in the catalogue and the next major removes it.

## Known limitations

- Unchanged from `1.3.0`: only `rsa-sha256` with relaxed/relaxed
  canonicalization, no Ed25519, no multiple signatures, no SMTPUTF8, no
  streaming attachments, and Sendust still publishes no DNS record.
- A failed transport has no reset; rebuilding it is the recovery.
- The core's module tree is smaller, so the phase and gate records of P04 keep
  describing the tree that phase built; this release's record says what was
  removed and why.

## Upgrade notes

Drop-in for `1.3.0`: no option, result or code changes. An error handler that
inspects `details` gains two fields it may already have expected, and one code
it can stop expecting (`PROTOCOL_REJECTED`, deprecated).

See the [release gate record](../gates/release-1.4.0.md).
