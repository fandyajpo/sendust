# Sendust 1.2.1

**Released:** pending — prepared 2026-11-24, from the CI `publish` job over OIDC,
tag `v1.2.1`.
**Package:** `@sendust/ts@1.2.1` with `@sendust/ts-<platform>` at the same
version.
**Dist-tag:** `latest`.

A metadata patch for the npm page. No runtime, API, result, error code, limit or
default changed; the code and the wire are byte-identical to `1.2.0`.

## Installation

```text
npm install @sendust/ts
```

## What changed

- **The npm page has links and keywords.** The published manifest now declares
  `homepage` (the documentation site), `bugs` (the issue tracker) and the keywords
  npm search uses. `1.2.0` shipped without them: its page linked only to the
  repository, and searching npm for "smtp" or "dkim" could not find it.
- **`ts/README.md` reads as a package page.** It is the text npm renders, so it
  now carries install, a quick start, both authentication modes, DKIM, the
  engine's guarantees, the seven native targets, runtime requirements, and links
  into the documentation — instead of a status line and one example.
- **The platform packages look related.** Each of the seven copies `homepage`,
  `bugs` and `keywords` from the facade, so a reader who lands on
  `@sendust/ts-linux-x64-musl` can find the project.

Why a patch and not a rebuild of `1.2.0`: a published npm version is immutable.
`1.2.0` went out on 2026-11-23 from the approved candidate `421ee02`
(facade `be29213d…`) before the metadata work landed; a second publish attempt on
the metadata candidate stopped at `already exists; refusing to replace it`, which
is the registry doing its job.

## Known limitations

- Unchanged from `1.2.0`: only `rsa-sha256` with relaxed/relaxed canonicalization,
  no Ed25519, no multiple signatures, and Sendust still publishes no DNS record.
- A published version cannot be corrected in place; anything wrong in `1.2.0`'s
  metadata had to wait for this release.
