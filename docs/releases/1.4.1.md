# Sendust 1.4.1

**Released:** 2026-11-27, from the CI `publish` job over OIDC, tag `v1.4.1`.
**Package:** `@sendust/ts@1.4.1` with `@sendust/ts-<platform>` at the same
version.
**Dist-tag:** `latest`.

A performance patch. The core sizes its buffers once, reuses one base64 line
buffer, walks body bytes instead of characters, and canonicalises a DKIM body
without a buffer per line. No public API, result, error code, limit or default
changes, and the emitted bytes are identical to `1.4.0`.

## What changed

- **The wire buffer and every MIME part are reserved once.** Preflight already
  measures the encoded bodies before anything is written, so the serializer uses
  that size instead of letting a 13 MiB buffer double its way up.
- **One base64 line buffer.** Each 57-byte chunk is encoded into the same reused
  buffer; a 10 MiB attachment used to allocate about 184 000 short strings.
- **Body normalization walks bytes.** CRLF, bare CR and bare LF become CRLF the
  same way; a multi-byte UTF-8 sequence contains neither terminator, so the byte
  scan is equivalent and copies whole runs.
- **Headers fold without a copy.** An ASCII value is folded directly, and the
  field prefix is pushed in place instead of built with `format!`.
- **A file attachment is read into a buffer of its own length**, still bounded by
  the per-file cap and the `take` limit.
- **DKIM body canonicalization** keeps one output buffer and one reusable line
  buffer instead of a buffer per line, with the trailing blank lines dropped by a
  deferred separator count.

## Measured

Release profile, pinned toolchain, `--test-threads=1`, one reference host, before
`1.4.0`'s core and after this release. The method and budgets are the ones in
[the performance budget](../qa/performance-budget.md); a metric that moved more
than 20% between two runs is listed as a range.

| Metric (median) | 1.4.0 | 1.4.1 |
| --- | ---: | ---: |
| 1 MiB text message, validate + serialize | 5 346 µs | 2 150–3 248 µs |
| 1 MiB linearity run | 5 102 µs | 2 151–2 387 µs |
| Small text message | 20 µs | 9 µs |
| Long and Unicode headers | 316 µs | 136–167 µs |
| 10 MiB attachment, serialize | 33 796 µs | 30 441–33 275 µs |
| 10 MiB file attachment, read | 2 360 µs | 1 037–1 515 µs |
| Peak, 10 MiB file read | 24.0 MiB | 10.0 MiB |
| Peak, 10 MiB attachment serialize | 61.1 MiB | 27.4 MiB |
| Peak, 20 MiB aggregate serialize | 81.1 MiB | 54.7 MiB |

The 10 MiB attachment serialization gains about 10% rather than more because the
remaining cost is the base64 encoder itself, which this release does not change.

## Known limitations

- Unchanged from `1.4.0`: only `rsa-sha256` with relaxed/relaxed
  canonicalization, no Ed25519, no multiple signatures, no SMTPUTF8, no streaming
  attachments, and Sendust still publishes no DNS record.
- The wire still exists twice in memory before `DATA`. Removing that copy is a
  streaming composition, which needs an ADR before code.
- The portable base64 encoder is now the remaining cost of a large attachment; the
  `simd` feature would roughly halve it, but changing the pinned feature set is a
  separate decision with evidence to collect on every target.
- The signing path has no budgeted metric, so the DKIM canonicalization change is
  covered by its tests rather than by a timing gate.

## Upgrade notes

Drop-in for `1.4.0`: no option, result or code change. Timing and peak memory
are the only observable difference.
