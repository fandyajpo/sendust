# Sendust 1.1.1

**Released:** 2026-11-23, from the CI `publish` job over OIDC, tag `v1.1.1`.
**Package:** `@sendust/ts@1.1.1` with `@sendust/ts-<platform>` at the same
version.
**Dist-tag:** `latest`.

A metadata patch. No runtime, API, result, error code, limit or default changed.

## Installation

```text
npm install @sendust/ts
```

## What changed

- **`repository.url` in the published manifests.** npm trusted publishing
  requires the field to match the GitHub repository for every package it
  publishes, so the facade and the seven platform packages now declare it. The
  platform manifests copy it from `ts/package.json`, so the two cannot drift.

Why a release for a manifest field: the project moved from a long-lived npm token
to trusted publishing (OIDC), and an unvalidated trusted-publisher configuration
expires two days after it is created. Publishing a patch both validates the
configuration and ships the field, instead of leaving the deadline to race a
feature release.

## Known limitations

- The publish itself is the first trusted-publishing (OIDC) run: provenance and
  the OIDC exchange are proven by it, not before it.
- Nothing else moved: the SMTP engine, the delivery engine, the caps and the
  result model are byte-identical to `1.1.0`.
