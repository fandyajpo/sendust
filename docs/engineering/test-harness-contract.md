# Sendust - Test Harness Contract

**Status:** P03-004 deliverable. Owns the fake SMTP/TLS test seams; [testing strategy](testing-strategy.md) owns the test layers that consume them.

## 1. Scope

This contract defines the deterministic, network-free harness that every Sendust SMTP, MIME, attachment, reliability, security, and QA test reuses. It replaces real relays and real certificates in tests. It never runs in production code and adds no test-only branch to `crates/sendust-core/src`.

## 2. Safety rules

1. Bind `127.0.0.1:0` only. Never `0.0.0.0`, a LAN address, or a fixed port.
2. No DNS lookup and no outbound connection to any non-loopback address.
3. No committed credentials; only generated dummy identities such as `alice@example.test`.
4. No external certificate authority, no real trust store modification, no network fixture download.
5. Every server instance shuts down deterministically; no leaked ports or threads.
6. Tests never sleep to wait for behavior; they wait for an observable event (a reply, EOF) or assert an injected delay directly.

## 3. Fake SMTP interface

Location: `crates/sendust-core/tests/support/mod.rs`, included by integration tests as `mod support;`. It uses only `std`; no Tokio, no lettre, no TLS yet.

- `FakeSmtp::start(Script) -> io::Result<FakeSmtp>` binds an ephemeral loopback port and serves every connection with the same script.
- `FakeSmtp::addr() -> SocketAddr` is the address a test dials.
- `FakeSmtp::trace() -> &Trace` exposes the observed commands and the DATA body.
- Dropping `FakeSmtp` stops the listener and joins the server thread.
- `Script` carries the reply for each stage: greeting, EHLO, STARTTLS, AUTH, MAIL, DATA, QUIT, and an unknown-command fallback. `rcpt` is a per-recipient reply list whose last entry repeats.
- `AfterBody::{Reply(Reply), Close}` decides the post-DATA disposition. `Close` drops the connection with no final reply, which is the observable `unknown` case.
- `Reply::lines(&[...])` produces multiline replies (`250-` continuation, `250 ` final).
- `Script::delay(Stage, Duration)` injects a stall before that stage's reply.
- `Trace::lines()` returns the raw command lines in order; `Trace::count_prefix("RCPT")` counts a verb; `Trace::body_text()` returns the DATA payload with CRLF line endings.

## 4. Delay injection

Delays are data, not test timing. A test that exercises a timeout injects the delay it needs and asserts the client-side outcome; the harness itself never picks a duration. Durations above one second are reserved for the P06/P10 clock-driven suites, which advance an injected clock instead of sleeping.

## 5. Fixture catalog - SMTP dialogue

| Fixture | Script | Expected client observation |
| --- | --- | --- |
| Accepted | default script | `220` greeting, multiline `250` EHLO, `250` MAIL/RCPT, `354`, final `250` |
| Mixed RCPT | `rcpt_replies([250, 550])` | Per-recipient accept and reject, one DATA for the accepted subset |
| All RCPT refused | `rcpt_reply(550)` | No DATA; overall rejected |
| Final DATA rejection | `after_body(Reply(451))` | Explicit negative final reply; rejected, no retry |
| Dropped after terminator | `after_body(Close)` | No final reply; connection ends; `unknown` |
| Greeting stall | `delay(Greeting, n)` | Connection established, banner withheld until the budget expires |
| Command stall | `delay(MAIL, n)` or `delay(Data, n)` | Stage timeout; session abandoned |
| Close stall | `delay(Quit, n)` | Bounded close drain |
| Unexpected command | any unrecognized verb | `500` fallback reply, recorded in the trace |

A hard TCP reset and an abrupt server close mid-DATA are P06 fault cases: producing a real reset requires socket options outside `std`, so P06 may add a dev-only dependency recorded in the dependency policy. The harness already produces the same observable contract, a missing final reply.

## 6. Fixture catalog - TLS

All material is generated by `scripts/generate-tls-fixtures.sh` and committed under `tests/fixtures/tls/`. It is test-only: never trust it, never install it, never use it outside this repository.

| File | Issuer | Validity / identity | Expected verification |
| --- | --- | --- | --- |
| `ca.crt` | self (root) | 2020-2040, CA | trust anchor |
| `valid-server.crt` | `ca.crt` | 2020-2040, `localhost` + `127.0.0.1` | succeeds |
| `self-signed.crt` | self | 2020-2040, `localhost` | fails: self-signed |
| `expired.crt` | `ca.crt` | 2018-2020 | fails: expired |
| `wrong-host.crt` | `ca.crt` | 2020-2040, `wrong.example` | fails: hostname mismatch against `localhost` |
| `incomplete-chain.crt` | `intermediate.crt` (withheld) | 2020-2040, `localhost` | fails: no issuer |
| `intermediate.crt` | `ca.crt` | 2020-2040, CA pathlen 0 | documents the withheld chain |
| `malformed.pem` | - | invalid DER | fails: unparsable |

Leaf server keys are EC P-256 and exist only so tests can serve those certificates.
The trust-anchor and intermediate signing keys are discarded by the generator:
nothing in this repository can sign a new certificate. `tests/fixtures/tls/`
must never contain `ca.key` or `intermediate.key`, and no key other than the five
leaf keys may appear there; `scripts/check-architecture.mjs` enforces both.
`scripts/check-secrets.mjs` scans the repository for credential shapes and exempts
only those leaf keys, and `.npmignore` keeps `tests/` out of the published package.

Regenerate with:

```text
scripts/generate-tls-fixtures.sh tests/fixtures/tls
```

TLS *serving* (implicit TLS and STARTTLS sessions) is implemented in P06-002, where lettre/rustls verification semantics are under test; this phase commits the fixtures and the regeneration script.

## 7. Evidence commands

```text
cargo test -p sendust-core --test harness_self_test
node scripts/check-architecture.mjs
```

`.github/workflows/ci.yml` runs the harness self-tests and verifies the committed TLS fixtures with `openssl verify` (positive for the valid chain, negative for every failure fixture).
