# Testing Strategy

**Applies to:** all phases.  
**Requirements:** C-21, NFR-007.  
**Related:** [quality gates](../planning/quality-gates.md), [reliability strategy](reliability-strategy.md), [security strategy](security-strategy.md).

## 1. Principles

1. **Test before implementation.** Each phase’s testing requirements are written before code exists; the plan is the test specification.
2. **Deterministic by construction.** No arbitrary sleeps, no real relays, no external network, no wall-clock dependence. Delays are injected; time is advanced explicitly.
3. **One behavior, one owning layer.** Rust core tests own protocol and MIME semantics. Binding tests own FFI ownership, async, and lifecycle. TypeScript tests own the public contract. Consumer tests own packaging and loading.
4. **Failure-first.** Every positive path has negative counterparts. Fault injection is a deliverable, not an afterthought.
5. **Evidence, not coverage theater.** A requirement without a test is a defect, regardless of coverage percentage.
6. **No flaky tests.** A flaky test is quarantined with a risk ID and cannot count as gate evidence.

## 2. Test layers

| Layer | Proposed location | Owns | Runs without |
| --- | --- | --- | --- |
| Rust unit | `crates/sendust-core/src/**` `#[cfg(test)]` | Validation, addresses, limits, MIME, state machine, errors | Node, network |
| Rust integration | `crates/sendust-core/tests/` | SMTP dialogue, TLS failures, timeouts, attachments, fake relay | Node |
| Binding integration | `tests/integration/binding/` | FFI conversion, ownership, async, lifecycle, error mapping | Real relay |
| TypeScript contract | `tests/integration/ts/` | Public types, results, errors, close/BUSY, ESM/CJS | Real relay |
| Type tests | `tests/types/` | Strict compile-time surface | Runtime |
| Consumer/packaging | `tests/consumer/` | Clean install, loader selection, negative binaries | Compiler, network |
| Security regression | `tests/security/` | Injection, redaction, TLS bypass, file safety | Real credentials |
| Performance | `crates/sendust-core/benches/` | Budgets, regressions | Network |

## 3. Fake SMTP harness

A scripted loopback server, implemented once in P03-004 and reused everywhere.

Requirements:

- Ephemeral loopback port; no fixed ports.
- Scripted per-stage responses: greeting, EHLO, STARTTLS, AUTH, MAIL, each RCPT, DATA, final reply.
- Configurable per-recipient replies (`250`, `550`, `451`, `421`).
- Configurable stalls at each stage, driven by a controllable clock.
- Abrupt close at any stage.
- Multi-line and malformed replies.
- TLS mode with generated fixtures.
- Exact command trace captured for assertions.
- Deterministic shutdown; no leaked ports or tasks.

The trace is the primary assertion surface. Examples:

- “No DATA command when every RCPT is refused or a 421 terminates the session; mixed RCPT sends one DATA transaction to the accepted subset.”
- “Exactly one transaction per send.”
- “No second connection after BUSY.”
- “No AUTH attempt after certificate failure.”

## 4. TLS fixtures

| Fixture | Expected |
| --- | --- |
| Self-signed | `TLS_CERTIFICATE` |
| Expired | `TLS_CERTIFICATE` |
| Wrong hostname | `TLS_CERTIFICATE` |
| Incomplete chain | `TLS_CERTIFICATE` |
| Malformed certificate | `TLS_HANDSHAKE` or `TLS_CERTIFICATE` |
| Valid test CA | success |
| TLS 1.1 only | `TLS_PROTOCOL` |

Fixtures are generated by a script, committed under `tests/fixtures/tls/`, and used only in tests. No production trust store is modified.

## 5. Filesystem fixtures

| Fixture | Expected |
| --- | --- |
| Regular file within cap | accepted |

| Regular file cap + 1 | `LIMIT_ATTACHMENT_BYTES` |
| Symlink to regular file | rejected |
| Directory | rejected |
| FIFO | rejected |
| Device (where available) | rejected |
| Missing path | validation/configuration error |
| Unreadable file | configuration error, path redacted |
| File that grows during read | `LIMIT_ATTACHMENT_BYTES` |
| File access without opt-in | `CONFIG_FILE_ACCESS_DISABLED` |

## 6. JavaScript boundary fixtures

- Buffer mutated immediately after `send` returns a Promise.
- Buffer detached immediately after the call.
- Multi-byte string and invalid UTF-16 input.
- Forced GC during an active send.
- Process exit without `close`.
- Double `close`, concurrent `close`, `send` during `close`, `send` after `close`.
- Two concurrent `send` calls: exactly one transaction, one `BUSY`.

## 7. SMTP fault matrix

| Case | Expected |
| --- | --- |
| All RCPT `250`, final DATA `250` | `accepted` |
| All RCPT `550` | `rejected`, no DATA |
| RCPT `421` after a prior `250` | Session closes; overall `rejected`, no DATA |
| Mixed `250`/`550` | One DATA transaction to the accepted subset; refused recipient remains rejected |
| Final DATA `451` | `rejected` (explicit negative reply); no retry |
| AUTH `535` | `AUTH_FAILED`; no MAIL |
| Reset after DATA terminator may have reached relay, before final reply | `unknown`; no retry |
| Greeting reset | protocol error; no retry |
| Reset during DATA before terminator may have reached relay | `unknown` if acceptance cannot be ruled out |
| Abrupt close before final reply | `unknown` |
| Connection refused | connection error |
| Connect stall 11 s | `TIMEOUT_CONNECT` |
| Command stall 31 s | `TIMEOUT_OPERATION` |
| Total stall 121 s | `TIMEOUT_TOTAL` |
| Close drain 126 s | `TIMEOUT_CLOSE` |

## 8. MIME conformance

- Golden fixtures: text only, HTML only, alternative, mixed, attachments.
- Parse every emitted message with an independent parser (`mail-parser`, test-only).
- Assert headers, content types, boundaries, transfer encodings, filenames, and BCC absence.
- Assert CRLF and legal folding.
- Assert wire-size accounting equals actual serialized length.
- Determinism: identical input produces identical bytes across runs.

## 9. Contract and type tests

- Strict TypeScript consumer (`strict`, `noImplicitAny`, `exactOptionalPropertyTypes`).
- No `any` in public results/errors.
- Error classes satisfy `instanceof` across ESM/CJS and wrapper/native boundaries.
- Unknown option keys rejected; limits cannot exceed hard caps.
- No `pool`, `retry`, `url`, `stream`, or required `abortSignal` in the public type surface.

## 10. Packaging tests

- Install the built artifact into a clean temporary project with no workspace access.
- Import via ESM and CommonJS; mixed-format process shares one implementation.
- Missing platform binary: clear error naming the expected package.
- Wrong-architecture binary: clear error, no fallback.
- No postinstall network access; no compiler required.
- Record loaded binary path and version.

## 11. Security regression

- CRLF, bare LF, NUL, encoded newline in every text field.
- Header-like display names and filenames.
- Reserved header override attempts.
- Password, body, and attachment markers absent from serialized errors and logs.
- Absolute paths absent from attachment errors.
- TLS bypass attempts via option, env var, or hidden flag.
- URL/stream attachment shapes rejected.
- Oversized inputs fail before connect.
- Panic test: invariant panic becomes `INTERNAL`, not a process abort.

## 12. Performance testing

- Budgets approved before measurement (P13-001).
- Fixed environment, repeated runs, median and spread reported.
- Measure validation, MIME, attachment read/copy, FFI overhead, send-path overhead, BUSY rejection, and close.
- Peak memory measured for worst-case caps.
- Regression threshold defined; exceeding it blocks the gate.

## 13. Coverage expectations

Coverage is diagnostic, not a target. Minimum expectations:

- Every public error code has a test.
- Every state transition has a test.
- Every cap has at-boundary and over-boundary tests.
- Every SMTP stage has a failure test.
- Every attachment file type has a test.
- Every public API method has success and failure tests.
- Every requirement maps to at least one test (P12-001).

## 14. Environment rules

- Fake relays only; test jobs should block network egress where feasible.
- No committed secrets; generated dummy credentials only.
- Test certificates are clearly scoped.
- Platform claims are tested on native runners, not emulation, unless explicitly labeled.
- Logs and traces are retained with the gate record.

## 15. Flake policy

1. Quarantine within one working session.
2. Record a risk ID and owner.
3. Quarantined tests do not count as gate evidence.
4. Do not use retries to mask flakiness.


## Multi-runtime test policy

Under ADR-0015, Node.js, Bun, and Deno are required MVP runtime targets. The native addon suite is blocking on all three pinned runtimes. Test the exact Sendust artifact, not only a framework compatibility probe. The suite includes native loading, Promise behavior, SMTP accepted/rejected/unknown outcomes, owned-buffer snapshot, BUSY, explicit close, close races, process shutdown, TLS verification, and stable error mapping.

The platform axis is tested separately and then combined with the runtime axis for every support claim. Record exact runtime version, OS, CPU, libc/minimum OS, artifact checksum, and CI run. Deno tests use local node_modules and explicit --allow-ffi. No test may rely on install scripts or external binary downloads.
